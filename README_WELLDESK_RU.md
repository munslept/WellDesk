## Как получить Windows EXE через GitHub Actions

1. Распакуйте ZIP. Установите Git на компьютере.
2. Создайте новый пустой репозиторий на GitHub без README, LICENSE и .gitignore.
3. Откройте PowerShell в папке WellDesk с Cargo.toml и выполните:

```powershell
git init -b main
git add .
git reset -- .github/workflows
git add .github/workflows/welldesk-windows.yml .github/workflows/welldesk-bridge.yml .github/workflows/third-party-RustDeskTempTopMostWindow.yml
git commit -m "Configure WellDesk client"
```

Если Git просит имя и email, задайте собственные значения командами
`git config user.name` и `git config user.email`, затем повторите commit.

4. Подключите ваш новый репозиторий и отправьте исходники:

```powershell
git remote add origin https://github.com/ВАШ_ЛОГИН/ВАШ_РЕПОЗИТОРИЙ.git
git push -u origin main
```

Команды с выбором workflow намеренно не добавляют остальные upstream-процессы
ночных сборок, публикаций и сборок других платформ. Не используйте вместо этого
загрузку папки через браузер: она может пропустить скрытые .github/.cargo файлы.

5. Откройте репозиторий → Actions → Build WellDesk Windows → Run workflow.
6. Дождитесь завершения. Первая сборка компилирует Rust, Flutter и зависимости
в GitHub Actions; она может быть длительной. На VPS ничего собирать не нужно.
7. Откройте завершённый запуск → Artifacts → WellDesk-Windows-x64.
8. Распакуйте артефакт. Внутри будет WellDesk-1.5.0-x86_64.exe — единый
самораспаковывающийся клиент, который можно разместить на вашем сайте.

Эта конфигурация сборки не запускает публикацию Release и не требует ключей
подписи. Полученный EXE не имеет цифровой подписи издателя. DLL, драйверы и
внутренние имена RustDesk сохранены, поскольку сборка и загрузчики зависят от них.
Иконки пока исходные; публичное имя приложения и описание продукта изменены.
Лицензия, авторские уведомления и ссылки на исходный проект сохранены.

## Перед размещением EXE на сайте

Проверьте на Windows с новым профилем приложения:

1. В Настройки → Сеть → ID/Ретранслятор отображаются указанные выше адреса и Key.
2. В главном окне появляется ID и готовность к подключению.
3. Два ПК подключаются через ваш сервер без аккаунтов и после входа в аккаунты.
4. При установке клиента служба и установленное приложение запускаются правильно.
5. API и веб-консоль доступны по http://185.180.230.199:21114.

На сервере должны быть открыты TCP 21114/21115/21116/21117 и UDP 21116.
Серверный публичный ключ должен совпадать с указанным Key.
Для распространяемого изменённого клиента приложите ссылку на соответствующие
исходники (этот архив или репозиторий) и сохраните LICENSE.

## Что проверено и что ещё не проверено

Проверены формат публичного ключа (32 байта), значения встроенных настроек,
приоритет пользовательских настроек в существующем Config::get_option/get_options,
структура workflow и его зависимости. Изменения исходных файлов сверены:

- libs/hbb_common/src/config.rs: начальное APP_NAME и три DEFAULT_SETTINGS.
  Это требуется для настройки сетевого ядра, UI, службы и профиля до загрузки конфигурации.
- flutter/windows/runner/Runner.rc: только FileDescription и ProductName.
  Это требуется для отображения WellDesk в свойствах Windows-программы.

Подмодуль hbb_common включён целиком на точном commit исходного архива:
229b904508364c8997aad0fb5af57effac859f60. Изменений остальных существующих
исходников нет. Новые workflow используют шаги исходной Windows-сборки,
ограничены x64 и сохраняют имя WellDesk.exe внутри самораспаковывающегося клиента.

В среде подготовки нет Windows, Flutter и Rust toolchain. Полная компиляция,
запуск workflow и реальное подключение этого клиента ещё не выполнены.
